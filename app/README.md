# Анық — помощник для прогулок по Астане (RAG)

Вход: точка пользователя + запрос свободным текстом («Я у EXPO, хочу что-то необычное на 1–2 часа, пешком»).
Выход: 1–3 места из `../data/poi.enriched.json` (OpenStreetMap + Overture Maps + Wikipedia + официальные сайты заведений; записи об одном месте слиты в одну), у каждого — почему, расстояние и время в пути (с пометкой, как оно
получено), время на месте, что делать, статус часов с источником и датой данных, плюс путь по улицам на карте.

## Запуск

```
cd app
uv sync
uv run python -m web                            # UI, http://localhost:8600
uv run python -m walks.cli --lat 51.0890 --lon 71.4160 --q "хочу что-то необычное на 1-2 часа пешком"
uv run pytest -q                                # тесты (test_scenarios.py читает ../data/poi.enriched.json)
uv run python scripts/precompute_walks.py       # прогрев кэша пеших маршрутов для записи демо без сети
```

CLI: `--time 23:00` (время), `--weather auto|off|<ощущаемая °C>` (+ `--pm25 80`, `--dark` для симуляции),
`--no-walking` (без Valhalla), `--no-llm`, `--offline` (ни одного сетевого запроса), `--simulate-google-down`.
Память (см. «Память»): `--keep-state` + `--follow-up --q "а поближе?"` (диалог), `--mark <poi_id>:<сигнал>` (анонимная отметка
места: `was_open`, `was_closed`, `has_socket`, `has_wifi`, `noisy`, `quiet`), `--profile <uuid|new>` + `--remember <флаг>` /
`--forget` (личный профиль).

явно; в вебе тот же ответ без пометок, факты те же).

### Провайдеры и цепочки

Звено цепочки — `provider:model[@profile]`; цепочки задаются в `LLM_CHAIN` (текст рекомендаций) и `LLM_INTENT_CHAIN`
(разбор), через запятую, по приоритету. Провайдеры:

- `gemini` — google-genai, ключ AI Studio. Настройки запроса зависят от семейства (`gemini_traits`): 2.5 — thinking budget 0,
  3.x — уровень MINIMAL/LOW. **Gemma** (`gemma-4-26b-a4b-it`, замеры вживую 16.10): любой thinking-конфиг даёт 400 («not
  supported for this model»). Сам сервис нестабилен (мгновенные 500, 504 через 30–45 с, 429 после серии запросов — на любых
  настройках), поэтому сравнивать можно только долю успехов: с `system_instruction` ~1 валидный ответ на 14 вызовов,
  с системным промптом, вставленным в начало сообщения, + `response_mime_type` + `response_schema` — 4 валидных на ~12
  (3–13 с) и два вырожденных тела («type-type-type…»), которые отсекает валидация → следующее звено. Поэтому для Gemma
  thinking и `system_instruction` не передаются, JSON-режим со схемой включён: на реальном запросе генерации только он
  хоть раз вернул валидный ответ (1 из ~13; варианты без схемы — 0 из ~26), текст Gemma при этом местами с дефисными
  артефактами («уника-нальных»). `gemma-4-31b-it` в момент замера отвечал 504 на каждый вызов. Gemma — запасные звенья
  в конце цепочки Google; дальше по цепочке — звенья других провайдеров.
- `openai` — любой OpenAI-совместимый `POST {base_url}/chat/completions` через httpx. JSON-режим — `response_format`
  (`json_object` по умолчанию, `LLM_PROFILE_<NAME>_JSON_MODE=json_schema|none`); если endpoint отвечает 400/422 на
  `response_format`, запрос повторяется без него (схема всегда дополнительно описана в промпте, ответ парсится и
  проверяется по той же pydantic-схеме, что и у Gemini; обрамляющий ```json допускается).

Endpoint OpenAI-совместимого звена — именованный профиль: `openai:<model>@<NAME>` берёт
`LLM_PROFILE_<NAME>_BASE_URL`, `LLM_PROFILE_<NAME>_API_KEY` или `LLM_PROFILE_<NAME>_API_KEY_FILE` (первая строка файла).
Без `@профиль`: `OPENAI_BASE_URL` (по умолчанию `https://api.openai.com/v1`) и `OPENAI_API_KEY`. Готовый профиль `ALEM`
(публичное API AlemLLM, `https://llm.alem.ai/v1`, модели `alemllm`, `gemma4`): достаточно ключа
`LLM_PROFILE_ALEM_API_KEY[_FILE]`, звенья `openai:alemllm@alem`, `openai:gemma4@alem`. Приватные профили (шлюзы) описываются
только в окружении или в неотслеживаемом `app/.env.<name>`; шаблон с плейсхолдерами — `app/.env.example`.

`WALKS_ENV=demo` (UI и CLI) подгружает `app/.env.demo` (в `.gitignore`), не перезаписывая уже заданные переменные.
Демо-цепочка: звенья Google → Gemma через AI Studio → приватный шлюз → AlemLLM → шаблон. UI и CLI показывают, какое звено
ответило (`provider:model@profile`, без URL), и всю цепочку попыток.

**Отказоустойчивость для демо**: `--simulate-google-down` (CLI, или `WALKS_SIMULATE_GOOGLE_DOWN=1`) принудительно роняет
каждое звено `gemini` — проверка, что ответ даёт следующий провайдер. `--offline` (CLI) или `WALKS_OFFLINE=1` (в UI это режим
сервера, переключателя в интерфейсе нет: строка «Без интернета: карта упрощена, живые данные недоступны», карта без подложки) — ни одного сетевого
запроса: шаблонный текст, погода и воздух «неизвестны», закат по формуле NOAA, пешие времена только из `app/.local/walk_cache.json`, иначе по прямой.

**Одинаковые условия на записи и на сцене** (`WALKS_DEMO_PIN=1`, включён в `.env.demo`; `walks/demo_pin.py`): у каждого записанного
запроса (сценария, запроса из `presets.DEMO_REQUESTS`, уточнения их диалога) фиксированное время (19.10.2026, 14:00; ночной — 23:00), ручная погода (обычная, для сценария про холод/смог — −25 °C /
PM2.5 80; везде помечена как ручная), пешие отрезки из отслеживаемого `../data/walk_cache.json` без сети и отслеживаемый сид
отметок людей `../data/city_feedback.json` (отметки посетителей на такие запросы не влияют, на остальные — влияют). Решение принимается на каждый запрос (`demo_pin.pins`): запрос вне записи («куда поесть» в 02:00)
отвечается по реальному времени и живой погоде, поэтому закрытое в это время место не бывает «открыто». UI, CLI и `scripts/warm_cache.py` идут через одну функцию
`demo_pin.recommend_pinned`, поэтому записанный ответ ищется под тем же ключом, под которым его спросит сцена.
`uv run python scripts/warm_cache.py` записывает `../data/demo_llm_cache.json` только через **публичные** звенья
(`gemini:*`, `openai:*@alem` с ключом `LLM_PROFILE_ALEM_API_KEY[_FILE]` или файлом `<Hackathons>/.alem-key`; приватные звенья
`.env.demo` на время записи исключаются, запись с неповторимым `model` отклоняется), затем прогоняет каждый сценарий ещё раз
только по записи и печатает таблицу `scenario → cached, model`; код выхода 0 только если у всех `cached=True`.
`--verify-only` — только эта проверка, без вызовов моделей. Таймауты живого запроса: звено OpenAI-совместимого профиля
обрывается на подключении за 3 с (недостижимый хост не съедает бюджет), звено — по своему лимиту (6 с разбор / 15 с генерация),
весь запрос (разбор + генерация) — за 15 с, затем шаблон.

## Языки интерфейса и ответа (қазақша / русский / English)

Переключатель «Қаз / Рус / Eng» (казахский первым) справа от заголовка. Пока выбор не сделан вручную, язык интерфейса и
ответа — язык последнего запроса (`walks.lexicon.detect_language`); ручной выбор перезаписывает ответ на экране на
выбранном языке (`recommend(..., language=)`). Все тексты ответа без ИИ (почему, что делать, заметки, бейджи, маршрут,
метки «чуть дальше / другая категория») написаны кодом на трёх языках: `walks/i18n.py` — ядро (шаблон, уточнения диалога,
профиль), `i18n.py` — интерфейс (`web/`: сервер и статика), `i18n_panels.py` — страницы «Данные» и «Город». Тест
`tests/test_i18n.py` держит те же `{поля}` во всех трёх версиях каждой строки. В промпт ИИ язык ответа уходит полем
`answer_language`. Описание места в шаблоне на казахском / английском берётся из Википедии этого языка или не
показывается (описание из OSM собрано по-русски).

## Конвейер

1. **Разбор запроса** (`walks/intent.py`). Сначала всегда правила ru/kk/en (детерминированно), затем ИИ уточняет
   (structured output, pydantic `Intent`; в промпте явно перечислены допустимые категории из `walks/models.py`).
   Итог — объединение: категории и ключевые слова — union (ИИ может добавить, но не стереть категории правил), флаги —
   OR. **Модель только сужает, никогда не расширяет**: режим (`mode`) принадлежит правилам (car / transit — только если
   пользователь сам назвал транспорт), время из текста приоритетно, а без него оценка модели зажата до 300 мин и до
   двух значений правил; поля `weather_hint`, `exclude_categories`, `halal`, `minor`, `refusal`, `mode_explicit`
   заполняют только правила. Нет ключа или упала вся цепочка `LLM_INTENT_CHAIN` (таймаут 6 с на звено) → остаются
   правила. UI показывает, что дали правила, что — ИИ.
   - **Гигиена ввода** (`walks/safety.py`): JSON, блоки кода, теги, base64/hex-мусор вырезаются из текста до разбора и до
     промпта (в них нет слов пользователя: `with_kids`, `night` из вставленного JSON флагов не взведут).
   - **Возраст**: несовершеннолетний в запросе («15-летних», «подросток», «школьники», «teenager», «жасөспірім») —
     `Intent.minor`, бары и ночная жизнь исключены; эмодзи 🍺 не перебивает контекст «с ребёнком / подростком».
   - **Отказ**: запрос про наркотики, интим-услуги или оружие — `Intent.refusal`; места не ищутся, ИИ не вызывается,
     ответ — «С этим не помогу…» (ru/kk/en, `i18n: refusal`), запрос не логируется. «Музей оружия» — это музей.
   - **Опечатки не переворачивают смысл**: пары антонимов («надолго» / «недолго») и слово с «не-/без-» не считаются
     опечаткой основы; «nothing fancy», «без изысков», «простенько» — бюджет low.
   - **Слова о погоде** («-25, холодно», «аяз», «дождь», «жара +35», «смог») — `Intent.weather_hint`
     (cold / rain / heat / smog): подбор считает погоду неблагоприятной, даже если живая неизвестна; жара — от +30 °C.
   - **«Только из мечети», «just left the mall»** — `Intent.exclude_categories`: этот тип места не предлагается.
   - **Числа о себе** (`walks/quantities.py`, поля заполняют только правила): `Intent.price_cap_kzt` («до 3000 тг», «5 мыңға
     дейін», «under 5000 tenge»; до 15 000 ₸ — ещё и `budget=low`), `Intent.group_size` («нас 8», «8 адамбыз», «party of 8»;
     компания не превращает вечер в ночной режим), возраст ребёнка ≤ 12 лет («a 5 year old») — `with_kids`.
   - **Назван конкретное место** (`Intent.landmark_refs`, `Intent.info_about`): «хочу в Байтерек» — цель; вопрос про место
     («какие часы у Хан Шатыра», «стоит ли идти в Нацмузей») — `info_about`; «рядом с Хан Шатыром» — только локация.
   - Категория `other` от модели никогда не заменяет и не дополняет категории правил; «ночной режим» от модели принимается
     только если ночь названа в тексте.
2. **Поиск кандидатов** (`walks/retrieve.py`, без LLM). Радиус доступности из бюджета времени и режима
   (пешком 4.5 км/ч, 40% бюджета — дорога туда-обратно, поправка ×1.25 на улицы; для чистой «прогулки» — парки, смотровые,
   достопримечательности — 50%: ходьба и есть занятие), по прямой (haversine). Если места запрошенной категории в радиусе нет,
   радиус ступенчато расширяется до ×1.5, и только потом добавляются другие категории (никогда фастфуд, бары, «другое»;
   для «прогулки» — только парк / смотровая / достопримечательность / кафе / музей). Фильтр по категориям,
   скоринг по ключевым словам (название / описание / теги) и флагам запроса, состояние часов работы на момент прихода
   (Asia/Almaty, парсер `opening-hours-py`): `closed` исключается, `unknown` остаётся со штрафом и пометкой — «открыто»
   без данных мы не утверждаем; в праздник описания с часами переписываются в «обычно: …; в праздник часы могут отличаться».
   Если мест нужной категории меньше трёх, добавляются другие и помечаются. Топ-10 (лучший кандидат каждой запрошенной
   категории остаётся в списке). При ≤ −15 °C ощущаемой или PM2.5 > 35, пока есть хотя бы одно помещение, парки, смотровые и
   площадки исключаются целиком (в карточке это объяснено), а не только понижаются в рейтинге. Минимальное время на месте
   (музей 60 мин, кино 120 мин…) должно помещаться в бюджет после дороги; превышение до 15 мин допускается с пометкой
   «впритык». Без указанного времени бюджет 60 мин, а для запросов с ребёнком / музеем / туристом — 120 мин.
   - **Время на месте против бюджета**: место исключается, если минимальное время его категории (кино 120, музей 60,
     ресторан 45 …) больше остатка бюджета после дороги туда и обратно больше чем на 15 мин (кино при бюджете 90 мин);
     превышение до 15 мин оставляет место с пометкой «впритык». Если после этого не
     остаётся ни одного кандидата, места оставляются, а в «почему» стоит пометка. Число исключённых — `filters.excluded_min_stay`.
   - **Сети и дубли**: кандидаты одной категории в пределах 150 м от ближайшей точки с похожим названием сливаются в одну
     карточку, представляет ближайшая, в заметках «Сеть: ещё N точек рядом». Название нормализуется (casefold, кириллица
     ru/kk → латиница, без знаков и пробелов), сходство — `rapidfuzz.fuzz.ratio` ≥ 85. Так «Blackбери» / «Блэкбери» /
     «BlackBerry» и «Пинта» / «Pinta» — одно место. Названия, придуманные кодом по категории, не сливаются. Что с чем слито —
     на странице «Данные» и в выводе CLI.
   Станции (`transit_station`) никогда не рекомендуются как места.
   - **Праздники** (`walks/holidays.py`): в государственный праздник или перенесённый выходной состояние «открыто» по OSM
     понижается до «неизвестно (праздник)» — часы в OSM описывают обычные дни. Список 2026 — с официального портала
     gov.kz; 2027 посчитан по правилу переноса из закона (источники и оговорки — в docstring модуля).
   - **Часы с официальных сайтов** (`collect/sites`, `walks/hours.py` `poi_hours`): `opening_hours` записи — строка OSM или, если
     у записи её не было, день-квалифицированная строка с сайта заведения (`field_sources.opening_hours.source = official_site`):
     карточка пишет «открыто по данным официального сайта», а `Recommendation.hours_source_url` — страница сайта.
     Если у записи есть обе строки и недельные расписания различаются (`hours_conflict`), `opening_hours` остаётся OSM-ным,
     заметка называет оба значения («Часы в OSM и на сайте расходятся: OSM …, сайт …»), уверенность не выше `medium`;
     когда именно сейчас один источник говорит «открыто», а другой «закрыто», состояние — `unknown` (`hours_issue = split`),
     «открыто» не утверждается. Часы сайта без дней (`hours_unqualified`: «с 10:00 до 22:00») никогда не решают
     «открыто / закрыто»: состояние `unknown`, заметка «на сайте: …, дни не указаны». Описание сайта (`description_official`)
     — настоящее описание: в «что делать» цитируется с атрибуцией, без предложений с часами и без утверждений, которых не
     подтверждает ни одно поле записи (`walks/claims.py`).
3. **Условия** (`walks/weather.py`, `walks/metno.py`, `walks/sun.py`). Прогноз — MET Norway locationforecast 2.0 по центру
   Астаны (CC BY 4.0 + NLOD 2.0; User-Agent проекта с контактом; ответ держится до `Expires`, затем перезапрашивается с
   `If-Modified-Since`; после 403/429 — пауза 15 мин; таймаут 4 с). Свежий METAR аэропорта и официальные предупреждения
   Казгидромета идут первыми, прогноз даёт осадки (`next_1_hours`) и всё, что станция не сказала:
   - ощущаемая температура ≤ −15 °C или осадки ≥ 2.5 мм/ч, либо воздух: PM2.5 > 35 мкг/м³ (только при `WALKS_AIR_DEMO=1`),
     дым / дымка по METAR, действующее НМУ Казгидромета →
     приоритет помещениям (музеи, ТЦ, кафе, кино/театры, коворкинги, развлечения), пешком не дальше 600 м, на улице не
     дольше 20 мин, причина пишется в «почему» (настоящая: значение PM2.5, дым / дымка, НМУ, слова пользователя).
     **Исключение — запрос с питомцем** (`walks/shelter.asks_outdoors`: собаку выгуливают на улице при любой погоде;
     «кафе с собакой» не в счёт): место запрошенного вида остаётся (внутри вида ближе — выше), карточка честно называет
     условия («…условия: неблагоприятные метеоусловия (НМУ) по данным Казгидромета — прогулку лучше сократить»), на
     улице не дольше 20 мин; другой вид показывается, только если места запрошенного вида не осталось (код проверяет и
     ответ модели). Остальные запросы, включая явный «парк» и прогулку по умолчанию, уходят в помещение;
   - после заката (или до восхода): парки, смотровые и детские площадки штрафуются, причина пишется в «почему». Закат и
     восход всегда считаются локально (формула NOAA, точность ~2 мин);
   - запрос не удался → «погода / воздух неизвестны», подбор по этой части не меняется.
   В UI («Условия» → «Другое время / погода») можно выбрать время сегодня и погоду «Как сейчас» / «Мороз −25°» / «Ливень» /
   «Смог» (десктоп: время — в строке «сейчас / через час / вечером» левой верхней плашки); в закреплённом демо этот выбор скрыт.
4. **Генерация** (`walks/generate.py`). Один вызов ИИ на все 1–3 рекомендации: модель получает только факты
   кандидатов, intent, округлённую точку и условия. Код проверяет ответ: `poi_id` не из кандидатов отбрасывается,
   расстояния, время и часы берутся из данных (не от LLM), предложения с расстояниями/временем/«открыто сейчас»
   вырезаются, уверенность ограничивается качеством данных. Источник данных в карточке определяет код по записи POI, а
   не модель; время на месте зажимается в диапазон категории (кино 120–150, музей 60–90, кафе 30–60, парк 30–60,
   достопримечательность 15–30, бар 60–120 …), затем в бюджет маршрута. Описание из Википедии
   (`description_source = wikipedia`) считается настоящим описанием, с атрибуцией.
   **Цепочка звеньев** (`walks/llm.py`, провайдеры — `walks/llm_providers.py`): `LLM_CHAIN` по порядку; 429/5xx/таймаут/
   ответ, не являющийся валидным JSON по схеме, → сразу следующее звено, без пауз (одинаково для обоих провайдеров). После
   503 или таймаута звено пропускается 120 с (circuit breaker, на каждое звено отдельно). Таймаут одной попытки — 15 с, а на весь
   запрос (разбор + генерация, все звенья) — жёсткий лимит 15 с (на разбор из них не больше 5 с); исчерпан — шаблон.
   Шаблон из данных — только если упала вся цепочка (в вебе без пометки, CLI пишет «без ИИ»).
   Текст модели, написанный не тем алфавитом, что язык ответа (латиница для en, кириллица для ru / kk), код не выдаёт за
   текст карточки: карточка получает текст из данных. Если записанный / закэшированный ответ не оставил ни одной карточки с текстом модели (другой язык ответа, все места
   заменены ближайшими «двойниками») и модели доступны (не `WALKS_REPLAY_ONLY`, не офлайн), цепочку спрашивают один раз ещё
   раз без кэша; это видно в `meta.generation_retry` (`live` — использован новый ответ, `failed` — повторный запрос не
   удался) и в блоке «Как получен ответ». С `WALKS_REPLAY_ONLY` и офлайн остаётся шаблон.
5. **Пешие времена** (`walks/walking.py`). Только для итоговых 1–3 рекомендаций и отрезков маршрута (режим «пешком»):
   публичный Valhalla (FOSSGIS, `costing=pedestrian`, таймаут 5 с, ≤ 1 запроса в секунду, честный User-Agent). Нет сети или
   ошибка → «по прямой, оценка» (прямая ×1.3, 4.5 км/ч); после первого сбоя сеть не дёргается минуту. На карточке и в
   маршруте всегда указано, чем получено время. Вместе со временем приходит форма пути: у закэшированных отрезков
   (`data/walk_cache.json`, поле `g`) она есть, стенд со своим Valhalla (`WALKS_VALHALLA_URL`) достраивает недостающие в памяти,
   публичный FOSSGIS страница не спрашивает. Карта рисует линию по улицам; где её нет — слабую пунктирную прямую, а минуты
   стоят с «≈».
6. **Мини-маршрут** (`walks/route.py`): до 3 точек, ближайший сосед от пользователя, итог «в пути + на точках + обратно»
   против бюджета; при превышении сначала сокращается время на точках (≥10 мин), потом отбрасываются точки.
7. **LRT-подсказка** (`walks/transit.py`): если рядом с пользователем (≤ 600 м) есть станция LRT, а рекомендация дальше 1.5 км
   и сама рядом (≤ 600 м) с другой станцией — «LRT: A → B (проверьте расписание)». Только названия станций из OSM: без времени,
   цен и без утверждения, что линия сейчас ходит.

Карточка места в веб-интерфейсе: название и вид, минуты в пути, статус часов (значок и слово: «открыто», «скоро
закроется», «закрыто»; у неизвестных часов — просто серое «часы неизвестны», без штриховки и без полосы дня) с полосой дня и
отметкой «сейчас» там, где расписание известно, расстояние (и «по прямой» / «по оценке» с «≈» у минут, если путь не по улицам),
вход, если он есть в данных, «почему», строка «Источник часов: … · данные на …» (её нет, когда источника нет: статус уже всё
сказал), кнопки «2ГИС», «Яндекс», «Позвонить». Остальные места — список «Ещё варианты (N)». «Сегодня рядом» — одна строка
«Сегодня рядом: 2 события ›», которая раскрывается (раскрыта сразу, если вопрос был о событиях). «Подробнее» открывает место
по задачам человека: «Сейчас» (статус, часы дня, источник и дата), «Как добраться» (путь, остановка, транспорт), «О месте»
(почему, что сделать, «Идея ИИ» — метка свободного совета, вход с источником, время на месте, отметки жителей), «Контакты»
(адрес, телефон, сайт) и свёрнутые «Источники» (ссылки, расписание как в источнике, дата данных; Wikipedia — с атрибуцией
CC BY-SA). Кнопки «2ГИС / Яндекс / Позвонить» закреплены внизу. Шрифт один (Inter, цифры табличные), шкала размеров — токены
`--fs-xs … --fs-xl` и радиусы `--r-sm … --r-xl` в `web/static/css/app.css`; пока ответ готовится, первые 300 мс страница молчит,
затем показывает форму ответа (две строки и одна карточка), а через 3 с — шаги работы ядра. Страница «Данные» показывает источники с лицензиями и датой снимка, полноту данных (доли мест с часами, телефоном, сайтом)
и измеренную честность ответов. Разбор каждого ответа (округлённая точка, intent, фильтры, кандидаты, погода, цепочка звеньев
`provider:model[@profile]`, время, JSON, ушедший в ИИ) в интерфейсе не показывается: он есть в поле `explain` ответа `/api/turn`
и в CLI.

## Память: диалог, отметки людей, личный профиль

Три слоя, все выключены или пусты, пока пользователь сам их не включит. Код: `walks/followup.py`, `walks/feedback.py`,
`walks/profile.py`; веб-интерфейс — `web/memory.py`.

**1. Диалог (только сессия, ничего не сохраняется).** Следующее сообщение, которое читается как уточнение, правит прошлый
запрос, а не начинает заново. Сначала правила ru/kk/en (`parse_follow_up`, сообщение ≤ 8 слов, без названия другого типа
места), затем — необязательно — второе мнение ИИ по цепочке `LLM_INTENT_CHAIN` только для короткого невнятного сообщения.
«а поближе?» — радиус не дальше 80% самого дальнего места прошлого ответа; «а без алкоголя» — без `bar_nightlife` и без
тегов с алкоголем (`amenity=bar|pub|nightclub`, `alcohol=yes`, `overture_category` bar/pub/…); «что-то другое» / «ещё» —
без уже показанных мест (и соседних точек той же сети); «а подешевле» / «подороже» — бюджет; «а если с ребёнком» /
«без ребёнка», «потише», «с розеткой» — флаги; «на час дольше», «ещё полчаса», «а на 2 часа» — бюджет времени; «а на машине».
Результат — новый `Intent` плюс `Constraints` (радиус, исключённые id, «без алкоголя»); `Conversation` хранит последний
intent, id показанных мест и округлённую точку. UI: беседа в одной ленте (прежние ответы сворачиваются в строки), чипы под ответом («Поближе», «Другие места», «Без алкоголя», … и «Новый поиск»);
CLI: `--keep-state` (сохранить состояние) и `--follow-up --q "а поближе?"`.

**2. Профиль (опционально, локально, редактируемо).** Переключатель «запоминать мои предпочтения» выключен по умолчанию;
пока он выключен, профиль не читается и не пишется. Профиль: флаги `with_kids` (+ возраст), `mobility` (коляска / кресло),
`quiet`, `budget`, `halal`, `no_alcohol`, `language`, `walk_pace`, `cold_tolerance`; список «был здесь» (`poi_id` + день);
счётчики понравившихся категорий. Запись: после ответа появляются чипы «Запомнить: с ребёнком?» (из разобранного intent),
флаг сохраняется только по клику; кнопки «Был здесь» / «Понравилось» — в «Подробнее» места (при включённом профиле). Чтение: флаги профиля вливаются в intent
**нового** запроса (то, что названо в запросе, побеждает: бюджет, язык), посещённые места штрафуются (−2.5; пока хватает
других, не предлагаются и в ИИ не уходят), понравившиеся категории слегка поднимаются (+0.3 за отметку, не больше трёх),
темп ходьбы масштабирует радиус (×0.8 / ×1.25), «мёрзну» / «холод переношу легко» сдвигает порог погодного правила
(−5 / −25 °C ощущаемой). В «почему» стоит «Вы отмечали, что ходите с ребёнком — это учтено». Хранение —
`app/.local/profiles/<случайный uuid>.json` (имя файла — только канонический uuid, `?u=` не может указать другой путь), uuid
живёт в `session_state` и, для демо, в параметре `?u=`. Окно «Память» (кнопка «Память» в верхней плашке) показывает «Что я о вас знаю»: каждый сохранённый пункт с
кнопкой «✕», ручное редактирование и «Забыть всё» (файл удаляется). Туда же CLI: `--profile <uuid|new>`, `--remember
with_kids`, `--forget`.

**3. Знание города от людей (общее, анонимное).** В «Подробнее» места: «Были здесь? Сообщите о часах» — «Открыто», «Закрыто», «Другие часы», «Всё верно»; «Что заметили?» — «есть розетка», «есть Wi‑Fi», «тихо», «шумно».
Отметка — запись `{poi_id, signal, date, weekday, hour_bucket}` в `app/.local/city_feedback.json`
(рабочая копия вне git, создаётся из отслеживаемого сида `../data/city_feedback.json`; сид клики не меняют): нет id пользователя, координат, id сессии; время — только день и часть суток (утро / день / вечер /
ночь). Одна сессия не может отметить одно и то же дважды. Эффект:
- «был: открыто / закрыто» — отдельный уровень доказательств по часам: «люди отмечали открыто (2 раза, последний 16.10)»
  рядом с «часы неизвестны» по OSM (`PeopleEvidence`, `hours_state` не меняется — «открыто по OSM» и «люди отмечали
  открыто» не смешиваются). Отметки старше 30 дней игнорируются, свежие весят больше (период полураспада 14 дней), отметка
  из другой части суток весит вдвое меньше, противоречивые отметки снижают уверенность («отметки людей расходятся»); если
  OSM говорит «открыто», а люди — «закрыто», уверенность карточки снижается, и это сказано в заметках;
- «есть розетка», «есть Wi‑Fi», «тихо / шумно» используются как атрибуты для «тихого кафе с розеткой», со ссылкой на
  источник: «по отметкам людей (…)»; Wi‑Fi и розетка по отметкам весят чуть меньше, чем тег OSM.

**Сид — демо-данные.** `data/city_feedback.json` изначально содержит 28 записей про 8 реальных кафе у EXPO, Mega Silk Way и
Байтерека; у каждой `"demo": true`, это не отметки реальных посетителей. UI, CLI и ответ помечают такие отметки «(демо-данные)».
Настоящие отметки добавляются без `demo`. `recommend()` читает отметки, только если ему передан `feedback=`
(UI и CLI передают; оценка `eval/` — нет, поэтому её результаты от сида не зависят).

## Прогрев кэша для демо

`scripts/precompute_walks.py` для 5 пресетов × 5 сценариев + «героический» запрос × время суток × условия забирает у Valhalla
пешие отрезки пресет → кандидаты (топ-10) и прогоняет полный конвейер без ИИ (так подтягиваются отрезки между местами).
Результат — `app/.local/walk_cache.json`; с ним запись демо не зависит от сети. Прерванный прогон можно повторить:
кэшированное пропускается. `--dry-run` только считает отрезки.

### Записанные ответы ИИ (`data/demo_llm_cache.json`)

Файл лежит в репозитории, только для чтения, и загружается при `WALKS_ENV=demo`. Он проверяется **до** цепочки ИИ и до кэша ответов этой машины (`app/.local/llm_cache.json`: запись чужой цепочки под тем же ключом не уводит демо с записанного пути), в том числе при `--simulate-google-down`. `WALKS_DEMO_CACHE=<путь|off>` подменяет или отключает файл. Это ускоритель демо, а не гарантия: офлайн-гарантия — шаблонный путь (`walks/generate.py`).

Обновление после изменения разбора, данных или `data/city_feedback.json` — из `app/`, на реальной квоте LLM:

```
uv run python scripts/warm_cache.py                # записать ответы и проверить воспроизведение
uv run python scripts/warm_cache.py --dry-run      # только вывести план (время и погода каждого сценария)
uv run python scripts/warm_cache.py --verify-only  # только проверка: каждый сценарий из записи, без вызовов моделей
```

Скрипт идёт тем же кодом, что UI и CLI под `WALKS_DEMO_PIN=1` (`walks/demo_pin.py`: фиксированное время, ручная погода,
пешие отрезки из `data/walk_cache.json`, сид отметок `data/city_feedback.json`), и отвечает **только публичные** звенья (`gemini:*`,
`openai:*@alem`); приватные звенья `.env.demo` на время записи исключаются. Один прогон: 13 запросов к пайплайну
(5 сценариев + 2 запроса видео из `EXTRA`: «мороз» в аэропорту при −25 °C и kk-запрос + 6 follow-up), около 20 вызовов ИИ. После записи каждый сценарий запускается ещё раз только по
записи (пустой рабочий кэш) и печатается таблица `scenario → cached, model`; код выхода 0 только если у всех
`cached=True`, иначе 1 (в том числе когда звено не ответило или ответило не публичное).

`data/walk_cache.json` — отслеживаемая копия кэша пеших отрезков (только публичные точки), единственный источник пеших
времён в демо-пресете: обновить — `scripts/precompute_walks.py --date 2026-10-19`, затем скопировать
`app/.local/walk_cache.json` в `data/walk_cache.json`.

## Оценка качества (`eval/`)

`eval/cases.json` — 41 кейс (место × время × погода × запрос; пять сценариев задания — дословно, `tz: true`), у каждого
`expected` (категории, дорога, время, помещения при −15°C / PM2.5 > 35, дети, доступность, честность «часы неизвестны»).
Время, погода и воздух подставляются из кейса (`walks.weather.manual_weather`), дорога — по прямой × 1.3.

```
uv run poe eval                                    # baseline и shipped (`poi.json`, `poi.enriched.json`), сводки, сравнение, ../docs/scenarios.md
uv run python -m eval.run_eval --data ../data/poi.enriched.json --mode llm --tz --pause 70   # цепочка ИИ, 5 кейсов задания (shipped; baseline — ../data/poi.json)
uv run python -m eval.report                       # пересобрать summary_*.md|json, comparison_*.md и docs/scenarios.md
```

Прогоны — `eval/results/runs_<датасет>_<режим>.jsonl` (рекомендации, вердикт по каждому кейсу), метрики —
`summary_*.md|json`, сравнение датасетов — `comparison_<режим>.md`. Проверки (`eval/metrics.py`) пересчитываются
независимо от самого поиска: часы работы заново по `opening_hours`, id — по датасету. У бесплатного ключа Gemini ИИ-режим
упирается в 429/503: между кейсами нужна пауза ≥ 60 с, иначе цепочка уходит в шаблон (видно в `model_link`).

## Приватность

- Координаты пользователя округляются до 3 знаков (~100 м) сразу на входе (`walks/pipeline.py`); дальше (расстояния,
  промпты, запросы маршрутов, UI) используются только округлённые значения. Точные координаты нигде не хранятся.
- В ИИ (первое отвечающее звено цепочки: Google AI Studio или OpenAI-совместимый endpoint профиля) на шаге разбора уходят
  текст запроса и черновик правил (категории, флаги; без координат); на шаге генерации — факты кандидатов, intent,
  округлённая точка. URL и ключи профилей не попадают ни в UI, ни в логи, ни в репозиторий.
- В Valhalla (сторонний сервер FOSSGIS) уходят округлённая точка пользователя и координаты 1–3 рекомендованных мест;
  `WALKS_WALKING=off` (CLI `--no-walking`) отключает это; переключателя в интерфейсе нет. Запросы погоды и воздуха содержат
  только фиксированные координаты центра Астаны.
- Текст запроса и координаты пользователя не пишутся в файлы и логи. На диск пишется только:
  - анонимный агрегат `app/.local/requests.jsonl` (`walks/reqlog.py`): час (без минут), id ячейки сетки 500 м, категории и
    флаги intent, радиус, число кандидатов и рекомендаций, счётчики `hours_state`; без свободного текста, названий и id POI.
    Пишутся только запросы изнутри Астаны (рамка 50.98–51.25 с. ш., 71.25–71.65 в. д.), отказы и запросы с профилем не
    пишутся. Отключается `WALKS_REQUEST_LOG=off`;
  - кэш пеших отрезков `app/.local/walk_cache.json` — **только отрезки между публичными точками** (место → место, пресет →
    место). Отрезки от выбранной пользователем точки живут в памяти процесса и на диск не попадают;
  - кэш ответов ИИ `app/.local/llm_cache.json` (`walks/llm.py`): структурированный ответ модели (для разбора —
    категории, флаги, ключевые слова; для генерации — тексты рекомендаций) под sha256 от (округлённая ячейка, intent,
    получасовой интервал, кандидаты, цепочка звеньев) — ни текста запроса, ни координат в открытом виде.
    `WALKS_LLM_CACHE=off` отключает; при `--simulate-google-down` и `WALKS_OFFLINE` кэш не читается и не пишется. Записанные ответы `data/demo_llm_cache.json` (только `WALKS_ENV=demo`) при `--simulate-google-down` читаются, а `WALKS_LLM_CACHE=off` и их отключает.
  - **только по клику и только анонимно** — отметки места в `app/.local/city_feedback.json` (слой «город»: `{poi_id, signal,
    date, weekday, hour_bucket}`; ни id пользователя, ни координат, ни id сессии, время — только день и часть суток);
  - **только при включённом переключателе** — личный профиль `app/.local/profiles/<случайный uuid>.json` (см. «Память»);
    запрос, в котором участвовал профиль, не попадает в `requests.jsonl`, профиль не попадает в `city_feedback.json`, а в ИИ
    уходят только флаги (не список мест, где вы были);
  - диалог («а поближе?») живёт только во вкладке браузера; CLI хранит его в `app/.local/conversation.json` лишь с
    `--keep-state` / `--follow-up` (там уточнённый intent, id показанных мест и округлённая точка, текста запроса нет).
- Данные мест — публичные POI из OpenStreetMap, Overture Maps, Wikidata и Wikipedia (см. «Источники и лицензии»). Личное хранится только в профиле, который вы включаете сами, и удаляется
  кнопкой «Забыть всё»; отметки людей анонимны по схеме (`tests/test_memory.py` проверяет, что в записи нет лишних полей).

## Ограничения

- Часы работы — только из OSM, официальных сайтов, реестра музеев и Wikivoyage; в shipped-базе они есть у 23,4 % записей (у записей из OSM — 23,1 %, см. `../docs/figures.md`), для остальных «неизвестно». Страница «Данные» и легенда карты считают места без остановок транспорта (29 из 2 294 записей, категория `transit_station`, `../docs/figures.md` §3), поэтому их число мест и доля часов чуть отличаются от `../docs/figures.md`.
- Пеший маршрут Valhalla не учитывает, что к моменту прихода место может закрыться: статус часов считается по модельному
  времени в пути на этапе поиска.
- Радиус поиска считается по прямой; улицы длиннее, поэтому реальный путь может немного выходить за радиус.
- Линия маршрута на карте — путь по улицам из формы пути маршрутизатора (у закэшированных отрезков она есть; стенд со своим Valhalla достраивает остальные); если уличной линии нет — слабая пунктирная прямая между точками, а минуты стоят с «≈».
- Работа LRT не проверяется: подсказка всегда с «проверьте расписание». Названия станций — как в OSM (там встречаются опечатки).
- Праздники 2027 — расчёт по правилу, а не официальный перечень; Курбан-айт 2027 помечен двумя датами.
- Отметки людей — отдельный, слабый уровень доказательств: «люди отмечали открыто» не равно «открыто по часам», не меняет
  `hours_state` и не заменяет часы OSM; закрытое по OSM место они не возвращают. Сид `data/city_feedback.json` — демо.
- Профиль и диалог не делают рекомендации «умнее» сами по себе: это флаги и исключения поверх тех же данных, а не обучение.
- Шаблонный текст без ИИ — на ru/en; для kk используется ru (ИИ отвечает на языке запроса).
