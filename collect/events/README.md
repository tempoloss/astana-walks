# collect/events — афиша «что происходит сегодня / сейчас»

Карточки событий **с первоисточников и серверных агрегаторов, чьи политики разрешают хранить факты** (вердикты
STORE из `collect/SOURCES.md` §14.3). Хранятся только факты: название, время (начало/конец/сеансы/часы), площадка +
адрес, цена как написана на странице, ссылка, источник, `fetched_at` и дословный фрагмент страницы (`evidence`). Описаний,
афиш-картинок и текстов постов нет (ГК РК ст. 974 п. 4: сообщение о событии — факт).

```
uv run python -m collect.events                      # обход всех источников → проверка → data/events.json (+ events_stats.json)
uv run python -m collect.events --only sxodim.com,alem.ai
uv run python -m collect.events --verify-only        # перепроверить data/events.json по кэшу, без сети
uv run python -m collect.events --ttl-hours 6        # кэш-страница моложе 6 ч повторно не запрашивается
uv run --with pytest python -m pytest collect/tests/test_events.py -q
```

Печатная афиша живёт часы: страница из кэша берётся, только пока моложе `--ttl-hours` (6 по умолчанию); повторный запуск
в этом окне не делает ни одного запроса и пишет тот же файл (идемпотентно). Источник, который не ответил, **не стирает**
свои прежние ещё не прошедшие события (инкрементально); ответивший — заменяет их. Прошедшее (конец + 3 ч, дата окончания
серии, «стоячие» площадки старше 14 дней) выкидывается при каждом запуске. Рекомендуемый ритм: раз в 3–6 часов.

## Источники

Все запросы идут через `collect.sites.fetch.SiteFetcher`: `robots.txt` хоста читается при каждом запуске (запрещённый путь
или нечитаемый robots.txt — не запрашивается), ≥ 1 с между запросами к хосту (больше, если robots.txt требует:
inastana.kz `Crawl-delay: 5`), `User-Agent: astana-walks/0.1 (hackathon; an8kk.sa@gmail.com)`.

| источник | что берём | robots / лицензия | кэденс | вердикт |
|---|---|---|---|---|
| `sxodim.com/astana/events/{today,week}` | карточки «цена, дата[ в время], площадка, адрес» (дата без года → ближайший к сегодня) | `User-agent: * / Disallow:` (пусто) | 3–6 ч | STORE |
| `www.inastana.kz/afisha` + страницы `/afisha/<id>/<slug>` | сеансы кино и концерты: площадка, адрес, прокат, времена сеансов дня, цены сеансов | `Crawl-delay: 5`, `/api*`, `?date=*` закрыты — не трогаем | 3–6 ч | STORE |
| `qazaqconcert.kz/posters`, `/poster/<slug>`, `/contacts` | афиши зала «Qazaqstan» ОКЗ: дата, зал, время, адрес (из контактов); залы других городов отбрасываются | `Allow: /` | 6 ч | STORE (собственная афиша) |
| `youticket.kz/events/<slug>` (по sitemap) | события города `astana`: площадка, адрес, **координаты**, сеанс, цена; `OPEN` — режим работы | `Allow: /`, sitemap в robots | 6 ч | STORE |
| `alem.ai/en/` | постоянная экспозиция: часы, цена билета, адрес и координаты | robots.txt отсутствует (404 = всё разрешено) | сутки | STORE |
| `t.me/s/sxodim_astana` | только посты со строками «📅 дата, время» и «📍 место»: факты + `https://t.me/<канал>/<id>` + «источник: @канал» (канал НЕ официальный орган) | robots.txt отсутствует | 6 ч | STORE (факты и ссылка) |

Не используем (по вердиктам §14.3): Ticketon (CONTRACT, оферта запрещает парсинг), Яндекс.Афиша / 2ГИС (RUNTIME),
Kassir (REVIEW), Eventbrite / Ticketmaster (нет данных по Астане).

### Что не удалось закрыть сегодня (честно)

- **gov.kz (ярмарки, зимние катки)**: сайт — JS-оболочка без серверного контента; публичный JSON `www.gov.kz/api/v1/public/…`
  на запрос с нашим User-Agent отвечает `400 notAllowed`. Обходить защиту (подменять заголовки) не будем: источник
  остаётся без сборщика, пока не будет разрешённого канала (договорённость с акиматом / официальный датасет).
- **Каток «Алау» (`mtexm.com/object/alau`)**: страница даёт только «ежегодно с октября по апрель проект «Массовые катания»»
  без сеансов и цен; сеансы и билеты — на `kazticket.kz` (недоступен с этого хоста / закрыт robots.txt). Без часов и дат
  «сейчас идёт» не утверждаем — сборщика нет.
- `mtexm.com/events` (календарь Барыс-Арены / Астана-Арены): площадка названа только свободным текстом новости — не парсим.
- `astana-dpkm.kz`: на главной свежих анонсов нет (последние 2025 г.). `visitastana.kz/events`: HTTP 500.

## Схема `data/events.json`

```json
{"schema": 1, "tz": "UTC+05:00", "fetched_at": "ISO UTC — самая старая из страниц, на которых держатся записи",
 "sources": {"sxodim.com": {"fetched_at": "ISO", "pages": 2, "events": 27}},
 "events": [{"id": "sxodim.com:77443", "source": "sxodim.com", "title": "...", "category": "Stand up",
   "kind": "event|run|sessions|standing",
   "start": "2026-11-07T19:00:00+05:00", "end": null,
   "date_from": null, "date_to": null, "sessions": [], "hours_raw": null, "hours_osm": null,
   "price_text": "от 13 000 тенге", "price_from": 13000,
   "venue": {"name", "hall", "address", "lat", "lon", "coords_source": "page|poi|null", "poi_id", "poi_name", "match": "name|address|null"},
   "url": "ссылка на карточку источника", "fetched_at": "ISO UTC", "also_listed": [{"source", "url"}],
   "evidence": [{"field", "url", "snippet", "fetched_at"}]}]}
```

- `event` — одно время; `run` — серия дат без часов (включая «дата без времени»); `sessions` — сеансы одного дня (кино:
  прокат клэмпится на день загрузки страницы; страница показывает сеансы текущего дня); `standing` — площадка с недельным
  расписанием (`hours_osm` строится `collect.sites.hours.to_osm`).
- Время — Астана, фиксированное UTC+5 (в `collect` нет `tzdata`).
- Цена: текст как на странице + `price_from` (наименьшая названная сумма). Для кино — цены сеансов без знака валюты на
  странице; приложение подписывает ₸ при показе.

## Привязка площадки к POI (`venues.py`)

По дисциплине `collect/sites/agree.py`: близость сама по себе не засчитывается. Площадка связывается с POI из
`data/poi.enriched.json`, только если (1) **имя согласуется**: слова имени площадки (без «, кинотеатр в городе Астана», с
отдельным «(псевдонимом)») совпадают с именем POI после `names.name_key` либо короче-имя — набор целых слов длиннее-имени
(«Хан Шатыр» внутри «Chaplin Khan Shatyr»; «Централ» ≠ «Центральная мечеть»; имя только из слов-типов — «Grill Bar» — не
доказывает ничего); несколько подходящих POI различаются адресом (улица+дом), затем номером дома, затем координатами
страницы (ближайший ≤ 300 м с запасом); POI дальше 800 м от координат самой страницы отбрасывается; либо (2) **адрес
совпал** (`match: "address"`, имя ничего не говорит): ровно один POI «площадочной» категории на той же улице и доме.
Несвязанная площадка сохраняет адрес и **не получает координат**, если страница их не дала (youticket.kz, alem.ai дают).
Координаты, взятые у POI, помечены `coords_source: "poi"`; страничные — `"page"`; при слиянии дубля первоисточник без
координат берёт страничные координаты дубля вместе с его evidence.

## Верификатор (`verify.py`)

Как `collect/sites/verify.py`, плюс проверка «значение выводимо из фрагмента»: каждый `snippet` обязан дословно найтись
(с точностью до пробелов) в кэшированной странице `url`; название — внутри фрагмента `title`, число дня и «ЧЧ:ММ» — внутри
`when`, адрес — внутри `address`, цена — внутри `price`, широта/долгота совпадают с числами фрагмента `coords`, часы —
с `hours_raw`. Не прошёл адрес / цена / координаты — факт удаляется; не прошло название, время или площадка — удаляется
событие. Привязка к POI перепроверяется теми же правилами. `--verify-only` не ходит в сеть.

## Дубли

Одно событие в нескольких источниках — одна запись: побеждает первоисточник (alem.ai > qazaqconcert.kz > youticket.kz >
inastana.kz > sxodim.com), остальные — в `also_listed`. Одно событие = старт в пределах 30 мин + согласие названий
(кросс-языковое, по фонетическому скелету слов) + согласие площадок.

## Файлы

`model.py` схема, даты; `sxodim.py`, `inastana.py`, `qazaq.py`, `youticket.py`, `alem.py`, `telegram.py` парсеры (чистые:
html → события); `venues.py` привязка; `dedupe.py` дубли; `verify.py` верификатор; `run.py` обход, сборка, запись;
`tests/test_events.py` + `tests/fixtures/events/*.html` (урезанные настоящие страницы).

Потребитель: `app/walks/events.py` (`events_near`, `nearby_events`; CLI `python -m walks.cli --events --lat … --lon …`).
