## Wins
- **Commons geosearch is the bulk P18-substitute**: `generator=geosearch&ggsnamespace=6&ggsradius=300&prop=imageinfo&iiprop=url|extmetadata` returns 50 files within 300 m of Bayterek, each with the exact attribution payload we must ship (`Artist` HTML, `LicenseShortName`, `UsageTerms`, `AttributionRequired`) — one request per POI coordinate, join key = lat/lon + 300 m radius, no Wikidata item needed.
- **Openverse per-name queries work for landmarks**: 71 (Байтерек), 119 (Хан Шатыр), 53 (Астана опера), 8 (Нур Алем); every item ships a ready `attribution` string + `license_url` + `foreign_landing_url` — STORE-legal verbatim.
- **Attribution string format** (both routes): `"{title}" by {creator} is licensed under {license} {version}. To view a copy of this license, visit {license_url}.` / Commons extmetadata equivalent.
- Crawl budget confirmed live: anon Openverse = 20/min burst + 200/day → 2316 POI ≈ 12 days one-query-each; prioritized crawl (landmarks first ≈ 300 queries) finishes in 2 days.

## Dead / rejected + why
- `image=*` OSM tag values: only 3 in Astana and all point at unlicensed news/agency URLs (pztv.kz, ulysmedia.kz, sostav.ru) — legally unusable; `photo=` tag: 0.
- Unsplash: API 401 + terms forbid automated bulk («non-automated, high-quality, and authentic experiences», scraper ban); `source.unsplash.com` dead since June 2024.
- Pexels/Pixabay: key-gated (401/400 live), attribution-in-UI obligations, low KZ yield → CONTRACT, not worth it for this DB.
- Chain logos: no licence grants third-party commercial display; Commons `{{Trademarked}}` explicitly warns «you have to ensure that you have the legal right» — skip, use text brand names.
- Mapillary as STORE: §5 scraping ban + signed-URL TTL; imagery is CC BY-SA but the API terms layer makes storage-at-scale non-compliant → RUNTIME deeplink only.

## Unverified leads
- Openverse authenticated key (register) — claimed higher quotas exist but numbers not verified; worth registering before the batch crawl.
- Commons geosearch beyond ggslimit=50 (continue token `cocontinue` returned) — full radius counts per POI unmeasured; do in the crawler.
- Named-park/mosque/mall Openverse queries («Зелёный бульвар», Хазрет Султан, Жастар) not all probed — pattern from 5 landmark queries suggests ~50% hit-rate for named attractions.

## Recommended pipeline + honest ceiling
1. **Per-POI Commons geosearch** (lat/lon, r=300, ns=6, iiprop=url|extmetadata, iiextmetadatafilter=Artist|LicenseShortName|UsageTerms|AttributionRequired) — primary; rate: 1 req/s against commons.wikimedia.org, 2316 requests ≈ 40 min.
2. **Openverse name-match** for POIs with distinctive names (start with 127 attraction_landmark + 25 museum_gallery) — fill richer/vertical shots; 200/day anon or register key.
3. **OSM `wikimedia_commons=*`** → 2 category joins (already have category crawler).
4. Panoramax (7 photos) + Mapillary deeplinks (RUNTIME) — street context only, viewer-embedded, never stored.
5. **Attribution payload shape** (one row per image, JSON): `{poi_id, image_id, source: "commons|openverse-flickr|openverse-wikimedia|panoramax", url, thumb_url, width, height, license_code, license_url, artist, attribution_required: bool, attribution_string, foreign_landing_url, distance_m}` — join key `poi_id` (Commons route: nearest geosearch hit within 300 m; Openverse route: name match verified by distance <500 m to avoid wrong-city matches).
6. **Honest ceiling**: with all STORE-legal routes combined ≈ **90–110 of 2316 cards (~4–5%)**: landmarks ~70 of 127, museum_gallery ~10–15 of 25, viewpoint 1 of 1, parks a handful, **cafes ~0 of 578, restaurants ~0–5 of 398, playgrounds ~0 of 328, bars ~0–5 of 243**. Street-context fallback (Panoramax/Mapillary runtime viewer) can visually cover downtown locations but cannot be stored. UI must ship a licensed-placeholder design for the other ~95% (category-agnostic illustration + weather overlay), not a per-place photo.
