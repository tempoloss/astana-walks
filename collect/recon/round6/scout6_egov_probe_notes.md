# Раунд 6 — основная нить: проверка обхода каталога data.egov.kz (17.10, живьём)

Скаут `EgovCatalogSweep` логирует «30 индексов с координатами / 15 с часами» по всем ~3944 `apiUri`. Основная нить проверила два его хита и нашла систематическую ловушку, которая меняет смысл всей таблицы.

## 1. Сегмент версии ОБЯЗАТЕЛЕН — подтверждено на уровне каталога
`api/detailed/<apiUri>` без версии отдаёт `{"data":[],"totalCount":0}` **не потому, что данных нет**, а потому что датасет версионированный; с `/v<N>` строки появляются:
- `kr_mam_madeniet_komitetinin_a` → bare `0`; `/v1` → **`totalCount: 40`**
- `state_schools` → bare `0`; `/v1` → **`totalCount: 7094`**
Текущую версию даёт `currentVersion = 'v1'` внутри `https://data.egov.kz/datasets/view?index=<apiUri>` (в `getmeta` поля версии нет — §15.1). ⇒ Валидирует правило §15.1 массово: скаутские «100+» без версии — артефакт пустого ответа/схемы, а не данных.

## 2. Наличие колонки «похожей на координату» ≠ координаты (главный negатив)
- `state_schools/v1` поля включают `lat`,`long`,`geo_coordi` — **реальные числа** (`"lat":"51.906716","long":"69.854728"`, `"geo_coordi":"51.906716, 69.854728"`), строка = школа в Акмолинской обл. ⇒ это настоящий координатный реестр.
- `kr_mam_madeniet_komitetinin_a/v1` поле `geopositio` заполнено **прозой, не точкой**: `"geopositio":"Бас музей, \"Көрмелер\" залы"` («главный музей, зал выставок»), а не широта/долгота; и регион строки — `Абай облысы` (Семей), не Астана. ⇒ «колонка с именем geoposition» в схеме ≠ координатный источник. Класс ошибки, который раунд уже ловил трижды (витрина аптек, «+3–4 POI», «БИН-мост»).

## 3. Астаны в этих двух — нет
`match {region_nam:"астана"}` по `state_schools/v1`,`private_schools/v1`,`higher_education_org1/v1` → **`totalCount: 0`** у всех трёх (агрегация по `region_nam` показывает только области: «область» 6600, «казахстанская» 1180, «акмолинская» 545…, города-респубзначения отдельно не баcket'ятся). Координатные школы Астаны live-подтверждены в ДРУГОМ портале — SDU `schools_reestr` (§16.3, 217/217 с lat/lon). data.egov.kz образовательные реестры, видимо, по областям.
⚠️ `match` по analyzed-полю (`region_nam`) — тот же анализаторный капкан §15.1 (токенизирует «Акмолинская область»→«область»); вывод «0 в Астане» здесь силён ровно настолько, насколько токен «астана» вообще встречается в поле — требует `terms`-среза по `s_ats_id`/`region_id` для достоверности. Оставлено скауту на доработку.

## Итог для §16.4
Полный каталожный перебор data.egov.kz через keyless `api/detailed` **реализуем** (механика ясна: enumerate apiUri → currentVersion со страницы → `/v<N>` → реальный int `totalCount` + проверка, что координатная колонка содержит числа, не текст). Но «30 индексов с координатами» из черновика скаута — это «30 схем с колонкой похожего имени»; после гейта «колонка = числовой lat/lon» и «в датасете есть строки Астаны» их кратно меньше. Точный список — в отчёте скаута, который обязан отличать DATA-verified от SCHEMA-only.
