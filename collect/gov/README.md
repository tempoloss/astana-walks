# collect/gov — часы и адреса гособъектов для граждан

ЦОН Астаны (gov4c.kz), реестр спортобъектов № 730 и каталог наборов акимата (data.egov.kz). Запуск из корня репозитория:
`uv run python -m collect.gov.<модуль>`. Всё, что идёт в сеть, уважает `robots.txt` и ≤ 1 запрос/с на домен
(`collect.sites.fetch.SiteFetcher`, UA `astana-walks/0.1 (hackathon; an8kk.sa@gmail.com)`, кэш `.local/http_cache.sqlite`).

| этап | модуль | выход | сеть |
|---|---|---|---|
| ЦОН | `cons.py` | `data/gov/facts/gov4c.kz.json` | да |
| реестр № 730 | `sport.py` | `data/gov/facts/data.egov.kz.json` | да |
| каталог акимата | `catalog.py` | `collect/gov/catalog.json` | да |
| RCA / витрина ЦОН | `rca.py` | `data/gov/facts/ps_centers.json`, `data/gazetteer/rca_streets.json` | да (keyless `api/detailed`) |
| газетир улиц | `gazetteer.py` | `data/gazetteer/astana_streets.json` (+ `ATTRIBUTION.md`) | да (zip 12 МБ) |
| кандидаты OSM | `osm.py` | `data/gov/osm_candidates.json` | да (зеркало Overpass) |
| проверка | `verify.py [--write] [--strict] [--dataset POI_JSON]` | — | нет (кэш) |
| привязка + применение | `apply.py` (последняя стадия `collect.build`) | `data/poi.enriched.json`, `data/poi_enriched_stats.json[state_registry]`, `data/gov/joined.json`, секции `data/coverage_delta.md` и `data/ATTRIBUTION.md` | нет |

`collect.build` = … → merge → sites → **gov** (`--no-sites` останавливается после merge). `apply.py` отказывается
работать с набором, где уже есть `state_registry_match`: сначала пересобрать базу.

## RCA (адресный реестр) и витрина ЦОН — `rca.py`

Keyless-окно `GET https://data.egov.kz/api/detailed/<index>?source={ES-DSL}` (без apiKey; портал сам документирует его
на `/pages/samples`; robots.txt отдаётся HTTP 404 = по RFC 9309 всё разрешено). Проверено живьём 2026-10-17:

- `ps_centers` — 555 ЦОН по стране, **11 строк Астаны (`Region ~ 710000000`)**. Это **витрина, не реестр**:
  все 11 помечены `IsMarkedToDelete: true`, координаты (`geoposition`) есть только у 2, и одна из них лжёт на
  ~4.3 км (строка «Азиа парк», ул. Кабанбай батыра, 21: точка сидит у «Нұр Әлем», реальный ТРЦ — 51.128, 71.412).
  Поэтому строки сохраняются как факты с `extra.geoposition` и `display: true` — **материал перекрёстной сверки
  gov4c-ЦОН, не источник координат** (перекрёстная проверка 2026-10-17: единственная пара с координатами,
  «Спец ЦОН, ул. 20-40, д.2», сходится с нашим OSM-матчем на 25 м; у остальных 9 строк координат нет вовсе).
- Срез адресного реестра (RCA, Комитет по правовой статистике Генпрокуратуры) по 6 районам: **85 256 зданий**
  (`s_buildings`, без координат — это поле у реестра отсутствует по схеме), **4032 топонима**, из них
  **3016 «УЛИЦА»** (`s_geonims`, тип 11) + словарь `d_geonims_types` (85 типов, ru/kk с сокращениями
  «көш.», «даңғ.»). `max(modified)` = 2026-10-15 — реестр живой, в отличие от OpenAddresses ≤2017.
- `ar_code` из реестра сделок с недвижимостью присоединяется к `s_pb` (помещения: rca premises → `s_building_id`
  → здание), **не** к `s_buildings` — это разные 16-значные пространства rca одного здания (проверено на строке
  2026Q3: `s_pb.rca 1201400020780451` → здание `0201400003247281`).

Правовая основа — Закон РК №401-V «О доступе к информации» (ст. 1 п. 5: открытые данные — свободное использование,
обработка, повторная публикация; ст. 7: бесплатно; ст. 10 п. 5 и ст. 17: публикация на портале открытых данных).
Срез улиц выгружается в **`data/gazetteer/rca_streets.json`** (id, ru, kk, бывшие имена из `old_path_*`, тип,
район; **без координат** — их нет в реестре) и работает в `collect.gov.geocode`:

- согласование по ключу (`same_address_alias` в `geocode.py`): адрес, написанный бывшим именем или русской
  словоформой, сходится с текущей улицей реестра (дом по-прежнему решает; 766 из 3016 улиц имеют `former`).
  Текст записи не переписывается — печатная форма страницы остаётся доказанной дословно;
- `address_kk` на POI: казахское написание улицы пишется только когда с адресом POI согласуется **ровно одна**
  улица реестра (`field_sources.address_kk`, источник `state_registry`, страница `api/detailed`); это поле данных
  с чистым акцессором `POI.address_kk_source_url()` в `walks.models`, UI его не читает.

## Не взято из тех же реестров (по дизайну, не по лицензии)

- **ЕРСОП** (объекты проверок, CC BY 4.0): это юрлица и их проверки, не места для прогулки; джойн к нашим POI
  проверен на срезе — 0 совпадений.
- **`real_estate_transactions`** (цены сделок, CC BY 4.0 / CC 3.0 NZ): цена квартиры — не свойство места прогулки;
  полезен только для городских слоёв вне пешего помощника.
- **Школы / вузы** (`schools_reestr`, NOBD, `state_schools`, все с координатами): учебные заведения — не POI
  прогулочного помощника (ребёнок ищет развлечения, а не уроки); хранить их список здесь незачем.

## Правила, которые нельзя нарушать

- **Координаты — только из сопоставления** (`geocode.py`): с элементом OSM (`osm_candidates.json`) или POI набора по имени
  **и** адресу. OpenAddresses-точки не хранятся и не используются (CRS неверен, снапшот старый), Nominatim-bulk нет.
  Нет совпадения → запись остаётся в `data/gov/facts` и `data/gov/joined.json` (`action: kept_unmapped`, `reason`),
  считается в статистике, **на карту не попадает**. «Нет совпадения» — факт о наших данных, не о мире.
  Ранги: 3 имя+адрес; 2 адрес и ЦОН-имя; 1 адрес (здание в OSM без имени ЦОН); 0 только имя (ЦОН-элемент OSM без
  адреса, район упомянут ровно в одной строке реестра — позиция не проверена по адресу, `reason` это говорит).
  Кандидаты дальше 150 м друг от друга — неоднозначность → unmapped.
- **Область часов.** ЦОН: `scope=venue` — день-квалифицированная строка идёт в `opening_hours` (только если у POI их
  нет, иначе `opening_hours_state`); «Прием … / Выдача …» — `opening_hours` = приём, выдача в `Hours.note`; время без дней
  не становится `opening_hours`. Реестр № 730: `rrr`/`rrk` = неделя администрации (приёмной СДЮСШОР), **`scope=
  administration`**, на POI лежит `admin_hours` (`raw`, `scope`, `registry`, `phone_raw`), никогда `opening_hours`
  (иначе вечерний `hours_state` соврёт «Алау закрыта»). ФИО руководителя (`fior`) не хранится.
- Телефон: на странице ЦОН нет телефона отделения (колл-центр 1414 — общий, не факт филиала); у № 730 это местные
  номера приёмной без кода города — остаются в `phone_raw` (в `admin_hours`), в POI `phone` не пишутся.
- Спорт-записи только **присоединяются** к существующим POI: офис спортшколы — не место для рекомендации.
- Категория ЦОН — `other` + тег `gov_service=cson` (в `Category` приложения нет «госуслуги»; новая категория в данных
  ломает фоллбеки, а `other` по умолчанию не попадает в выдачу без явного запроса).
- Вывод каталога (`catalog.json`): «акимат публикует N наборов; координат нет ни в одном» — это утверждение про
  **опубликованные строки** (схема + значения первой страницы), не про мир.
- Зеркало Overpass отдаёт теги некоторых `way` в двойной кодировке (UTF-8 прочитан как cp1252): `osm.fix_mojibake`
  чинит, элемент помечен `encoding_repaired`.

## Как это подключено к диалогу (`gov-wire`)

Явный запрос госуслуги («ЦОН в субботу работает?», «справку получить», ХҚКО, «public service centre», translit «tson»)
идёт обычным поиском, но особым образом:

1. `lexicon_extra.py` — концепт `state_service` → категория `other`; `retrieve._gather` оставляет `other` только для записей
   с тегом `gov_service=cson` и только если `other` запрошена; `radius.backfill_ok` не добирает кафе/парки к короткому списку
   ЦОН. ЦОН не находятся по словам имени (`dialog_named`) и не попадают в чужие ответы.
2. `models.POI`: `admin_hours`, `opening_hours_state`, `state_registry_match`, `is_state_service()`; ярлыки источника
   `state_registry` («по данным ЦОН (gov4c.kz)», kk / en) — `hours_state_open_gov`, `fact_open_gov`, `by_gov`, `src_gov`
   (`walks/i18n_gov.py`, влиты в `STRINGS`).
3. Карточка: одна строка `Place.signal` (`kind: "state_registry"`) = `gov_hours.gov_hours(...).line` для запрошенного дня;
   ответ — одно предложение с интервалом дня и источником; «в воскресенье ни один ЦОН не работает» — по данным gov4c.kz.
   Сегодняшний день / без дня = «сейчас» (час прихода учитывается), день вперёд = этот день в 10:00.
4. Часы реестра спорта №730 (`admin_hours`) никогда не влияют на открыто/закрыто; они только дописываются к ответу про
   часы объекта: «график администрации … — это не часы работы самого объекта».

Модульный API (JSON): `walks.gov_hours.lookup(load_dataset(), when, kind="cson", near=(lat, lon))` -> `[GovHours]`
(`dataclasses.asdict`); CLI: `uv run python -m walks.cli --gov-hours --q "ЦОН в субботу" --lat 51.09 --lon 71.42`.
