# Лицензии и обязательства по источникам

Проверено 2026-10-17 по первоисточникам (тексты лицензий, страницы условий, тексты законов). Цитаты дословные, на языке оригинала; рядом ссылка. Это инженерное чтение текстов, не юридическая консультация: перед платным запуском нужен юрист (раздел 7).

Где что лежит: лицензия файлов `data/` — [`data/NOTICE.md`](../data/NOTICE.md); строки атрибуции — [`data/ATTRIBUTION.md`](../data/ATTRIBUTION.md); тексты лицензий, которые обязаны ехать вместе с данными — [`LICENSES/`](../LICENSES/) (ODbL-1.0, Apache-2.0, CDLA-Permissive-2.0); Notice Foursquare — [`data/NOTICE_overture.txt`](../data/NOTICE_overture.txt).

Принцип продукта: источник годится как STORE, только если его можно скачать, хранить и использовать в платном продукте. «Для продакшена» ниже — что нужно сделать, чтобы это осталось правдой при платном запуске.

## 1. Что нашла эта проверка

Подтвердились: Overture `places` не имеет одной лицензии на тему, она задана вкладчиком; 151 запись Foursquare под Apache-2.0 (пересчитано по `data/overture_places.json`: meta 8 118, AllThePlaces 234, Foursquare 151, Microsoft 86, PinMeTo 1, всего 8 590, у каждой записи ровно один вкладчик); датасет Zenodo — CC BY 4.0 с теми же авторами (`zenodo.org/api/records/15769359`: `license.id = cc-by-4.0`); бесплатный API Open-Meteo — только для некоммерческого использования; ссылка на источник в Приказе № 267 есть.

## 3. Overture: что именно проверено

- Страница https://docs.overturemaps.org/attribution/ для `places` перечисляет вкладчиков по отдельности и не называет лицензии темы целиком; руководство https://docs.overturemaps.org/guides/places/ говорит: «Places is published under the CDLA Permissive 2.0 and Apache 2.0 licenses, depending on the source.» и «Joining CDLA Permissive 2.0 data to OpenStreetMap is permitted, but the resulting data may need to carry the Open Database License (ODbL) if it is a derivative database.» Именно этот случай у нас: `poi.enriched.json` — ODbL (раздел 4).
- Лицензия записи берётся из `places[].sources[].license` файла `data/overture_places.json`. Пересчёт 2026-10-17: 8 590 записей, у каждой один вкладчик, пары (датасет, лицензия): `meta`+CDLA 8 118, `AllThePlaces`+CC0-1.0 234, `Foursquare`+Apache-2.0 151, `Microsoft`+CDLA 86, `PinMeTo`+CDLA 1. В `poi.enriched.json` после слияния дублей на запись Overture ссылаются 848 карточек (свой `overture_id` или id поглощённой записи; пересчёт 2026-10-18): meta 766, Foursquare 45, Microsoft 29, AllThePlaces 10 — карточка может ссылаться на двух вкладчиков.
- Copyright Foursquare: страница Overture — «Copyright 2024 Foursquare Labs, Inc.»; страница Notice на момент чтения — «© 2026 Foursquare Labs, Inc.». Оба текста сохранены как есть.
- Apache-2.0 §4 выполнен так: копия лицензии (`LICENSES/Apache-2.0.txt`), уведомление об изменениях и Notice дословно (`data/NOTICE_overture.txt`). Notice сам рекомендует для плоских файлов: «include this NOTICE.txt file, which may be modified to include an additional notice of your changes/modifications».
- Чего я не нашёл: отдельного NOTICE в репозитории `OvertureMaps/data` и в корзине релиза — запросы по угаданным адресам вернули 404. Единственный первоисточник текста — страница Foursquare, на которую ссылается Overture.

## 4. ODbL: что с нашей базой, ИИ-текстом и картой

- **Производная база.** `poi.enriched.json` построен из выборки OSM (1 501 место в `poi.osm.json`; руководство OSMF: «Less than 100 Features» — несущественно, «The systematic extraction of all eating places within an area … would be considered to be systematic») плюс записи других источников. По ODbL 1.0 это Derivative Database (раздел 1.0 и 4.4 b: извлечение существенной части в новую базу). Лицензия файла как базы — ODbL 1.0, обязанности — таблица выше и `data/NOTICE.md`.
- **Содержимое с другими лицензиями.** ODbL 2.4: лицензия «does not cover any rights … in individual Contents». Вкладчики Overture (CDLA/Apache/CC0) и Wikidata (CC0) не мешают: ODbL 4.4 d запрещает добавлять только содержимое, несовместимое с правами по ODbL, а разрешительные лицензии совместимы. Извлечения Википедии (CC BY-SA 4.0) входят как отдельные короткие тексты со ссылкой; CC BY-SA 4.0 §4(b) делает «Adapted Material» базу целиком только когда в неё включена «all or a substantial portion» базы данных Википедии — у нас не более 51 короткой выдержки. Это место — на проверку юристу.
- **Текст ИИ — Produced Work.** ODbL 1.0: «Produced Work – a work (such as an image, audiovisual material, text, or sounds) resulting from using the whole or a Substantial part of the Contents (via a search or other query) from this Database, a Derivative Database…». Карточка с текстом, разобранный запрос, отрисованный маршрут — результаты запросов к базе. Общественное использование Produced Work требует только уведомления (4.3) и **не** делает сам текст производной базой (4.5 b: «Using this Database … to create a Produced Work does not create a Derivative Database for purposes of Section 4.4»). Но 4.4 c связывает: публично используемый Produced Work из производной базы означает, что сама база публично используется, а значит под 4.4 (ODbL) и 4.6 (дать копию). Для публичной платной службы это значит: выложить `poi.enriched.json` и способ его сборки открыто. Руководство OSMF о моделях машинного обучения: «Predictions made using such a model are not implicated by ODbL. However, … if a Produced Work is used to extract, copy, or recreate substantial parts of the OpenStreetMap data, it is considered to be a Derivative Database» — поэтому конечные точки, отдающие места списком (`/api/districts`, `/api/city/*`), — это база, не Produced Work (руководство о Produced Work: «Database dumps are usually not Produced Works»).
- **Карта.** Отрисованная карта — Produced Work, для интерактивной карты подходит атрибуция в углу (руководство по атрибуции OSMF: «For a browsable map (e.g., embedded in a web page or application), the credit should typically appear in a corner of the map.»). Сейчас это строка в легенде карты: внизу слева на десктопе, второй строкой верхней панели на телефоне, всегда на экране.
- **Что остаётся закрытым.** Код приложения, журнал запросов, отметки людей, ранжирование, подсказки для модели — отдельные от базы. ODbL 4.5 a: «You are not required to license Collective Databases under this License if You incorporate this Database or a Derivative Database in the collection». Условие: не вливать их в `poi.enriched.json`.

## 5. Лицензия кода репозитория: решение владельца

В корне нет файла LICENSE, в `pyproject.toml` нет поля `license`; есть только лицензия вложенной библиотеки MapLibre и тексты в `LICENSES/` для данных. Я не выбираю: это решение владельца. Два варианта.

| вариант | что даёт | цена |
|---|---|---|
| **A. Permissive (Apache-2.0 или MIT)** | любой может использовать, форкать, встраивать в закрытый продукт, в том числе конкурент или город без вас; Apache-2.0 добавляет явную патентную лицензию и требует сохранять Notice; код совместим с ODbL-данными, потому что они отдельная база | отказ от монополии на код; платный продукт строится на сервисе, данных и бренде, а не на закрытости кода |
| **B. Закрытый код, «все права защищены»** | вы сохраняете исключительное право на код; для жюри, партнёров и кейс-чемпионата достаточно доступа по приглашению | публичный репозиторий без лицензии — по умолчанию «никто ничего не вправе»: форк и вклад чужих людей невозможны; обязательства по данным не уходят — `data/` всё равно остаётся ODbL и должна быть открытой для получателей, значит нужен отдельный открытый репозиторий данных |

Любой выбор не меняет раздел 2: лицензии данных и сторонних сервисов остаются как есть.

## 6. Интерфейс: что сделано и что осталось

Сделано в ветке `attrib-ui` (только строки и ответы сервера, разметка страницы не менялась; после перерисовки интерфейса `footer` стоит в разделе «Атрибуция» страницы «Данные»): `footer` и раздел «Источники» (`app/i18n.py`, `app/i18n_panels.py`, kk/ru/en) называют лицензию Overture по вкладчику (Meta, Microsoft, PinMeTo — CDLA-Permissive-2.0; Foursquare — Apache-2.0, © Foursquare Labs, Inc., со ссылкой на Notice; AllThePlaces — CC0), уведомление ODbL с адресами https://www.openstreetmap.org/copyright и https://opendatacommons.org/licenses/odbl/1-0/, «Data from MET Norway», «Weather data by Open-Meteo.com» с адресом https://open-meteo.com (когда PM2.5 включён оператором), OpenFreeMap © OpenMapTiles, адрес https://www.openstreetmap.org/fixthemap, метку «публичный сервер — для небольшой нагрузки» у Valhalla FOSSGIS (при `WALKS_VALHALLA_URL` её заменяет «свой сервер на OSM»). `/api/districts` и `/api/city/export/*` несут атрибуцию OSM в ответе: поля `attribution` и `license` в GeoJSON, первая строка `# Contains information from OpenStreetMap …` в CSV. `app/README.md`, раздел «Источники и лицензии», приведён к тем же строкам.

Осталось (нужна правка разметки или JS): разделы «Атрибуция» и «Источники» страницы «Данные» выводят адреса обычным текстом, потому что строки выводятся обычным текстом (разметки ссылок в них нет); кликабельные ссылки, включая ссылку Open-Meteo «рядом с данными», появятся, когда страница научится ссылкам; эти разделы видны только на странице «Данные», на главном экране атрибуцию несут легенда карты (ссылки на OpenFreeMap, OpenMapTiles, OpenStreetMap и ODbL кликабельны) и строка «Источник часов: …» на карточке.

## 7. Перед платным запуском

1. Юрист: ODbL для публичной платной службы (раздел 4), ShareAlike для текста ИИ по Википедии, база OpenAddresses без лицензии, возраст 18+ в условиях Gemini.
2. Заменить сервисы, чьи условия не допускают коммерции: Valhalla FOSSGIS → свой сервер; Open-Meteo → платный план или MET Norway; Gemini → платная квота; публичный Overpass и Nominatim → только для разовых выгрузок.
3. Письма: Казгидромет (показ ОЯ/НМУ в платном приложении), НАО «Правительство для граждан» и акимат (повторное использование реестров).
4. Выложить `poi.enriched.json` и `collect/` по ODbL; держать `data/NOTICE.md`, `NOTICE_overture.txt`, `LICENSES/` в поставке.
5. Решение владельца по лицензии кода (раздел 5).
