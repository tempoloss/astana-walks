## Счёт

3 записи в `findings.jsonl`, все с серьёзностью minor: `profile-switch-wheelchair-1`, `console-reporter-1`, `map-overlap-offline-1`. JS-ошибок (`pageerror`): 0. Запись `console-reporter-1` — отказ ресурса (503), а не исключение JS.

Расхождение с отчётом автора прогона: он пишет «2 major — падения драйвера, оставлены в jsonl»; в `findings.jsonl` major-записей нет, финальный файл содержит только перечисленные три minor. Файлы правильнее.

## Находки

1. **[minor] `console-reporter-1`** — «Сообщить о часах» на стенде записанных ответов падает с 503: сервер запущен с `WALKS_FEEDBACK=off`, `/api/report` честно отвечает `503 marks_off`. Пользователь видит «Не удалось сохранить отметку», кнопки остаются активными — корректная деградация, но на публичном демо-стенде (тоже только чтение) горожанин всегда увидит отказ; нужно либо писать отметки во временный файл стенда, либо сказать «в демо отметки не сохраняются». Скриншот: `shots/reporter-03-reported.png`.
2. **[minor] `map-overlap-offline-1`** — на карте в офлайн-режиме на телефоне подписи «1 Фаттуш» и «3 Национальная академическая библиотека…» перекрываются: точки рядом, подпись третьего места длинная и не обрезается. Данные верны. Скриншот: `shots/offline-03-answer-s1.png` (рядом — `shots/offline-02-answer-s1.png`).
3. **[minor] `profile-switch-wheelchair-1`** — на телефоне «Память» спрятана за бургер-меню; автоподбор по тексту не нашёл кнопку включения профиля (список слов в проверке неполон), диалог при этом открывается через бургер — для пожилого пользователя лишний шаг. Скриншоты: `shots/wheelchair-02-profile.png`, `shots/parent-02-memory.png`.

Замечено вне автопроверок, по скриншотам:

- на телефоне карточка «Другие места» обрезает длинные название и категорию («Детская пло…» / «детская площа…») — `shots/parent-04-chip-kids.png`;
- «куда сходить на коляске рядом» разбирается как непонятый (чипы «Поесть / Кофе / Погулять»): «на коляске» не распознано как доступность, доступность работает через профиль и чипы, а не через свободный текст — `shots/wheelchair-03-wheelchair-q.png` (тот же эффект в диалоговом раунде: `d32[0]`, `d34[0]` в `docs/fuzz/DialogueFuzz2/findings.jsonl`).

## Что работало

- Записанные ответы отдаются мгновенно (< 0,5 с) и честно помечены в интерфейсе («Текст по правилам из данных, без ИИ» / «записанный ответ») — `shots/pensioner-03-answer-s1.png`.
- Опечатки читаются, ответ по существу на обоих языках — `shots/pensioner-04-typo.png`, `shots/tourist-04-typo-en.png`.
- Казахский сценарий отдаёт казахский ответ без смешения языков, смена языка посреди диалога переспрашивает последний ответ — `shots/kazakh-02-kk-answer.png`.
- Офлайн: баннер «нет интернета: карта без подложки, точки и путь видны», маршрут и карточки живые, сетевые ошибки страницу не роняют.
- Перезагрузка восстанавливает диалог из вкладки; «Ещё варианты», «Подробнее», смена точки, чипы уточнений работают на обоих вьюпортах; клавиатурный Tab держит видимый фокус — `shots/pensioner-07-tab-focus.png`.
- Ссылки 2ГИС / Яндекс в карточках — пешеходные deeplink'и корректного формата (проверены `href` без открытия).

## Замечание о записях демо (не дефект интерфейса)

`scripts/warm_cache.py --verify-only` на чистом дереве этого коммита: 9 из 13 сценариев воспроизводятся из `data/demo_llm_cache.json`; 4 («Mega Silk Way», «Необычная ночная активность» и два уточнения к «Mega Silk Way») не находятся по ключу — запись сделана до изменений intent и времени на месте (категория «mall» теперь отбрасывается правилами, время на месте для баров 30–120 мин). В режиме replay-only такие запросы честно отвечают шаблоном «не записан». Число взято из отчёта автора; в каталог результат проверки не копировался.
